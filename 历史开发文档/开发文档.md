## 1. 当前主开发流程

现在推荐的实际工作方式如下。

| 阶段 | 在哪里做 | 主要动作 |
| --- | --- | --- |
| 写代码 | 机载电脑 / Orin NX | 直接在 `~/catkin_ws` 里用 Codex 修改代码和脚本 |
| 编译 | 机载电脑 / Orin NX | 在真实 ROS 工作空间里 `catkin_make` |
| 地面验证 | 机载电脑 / Orin NX | 拆桨、看话题、看 RViz、检查日志 |
| 实机验证 | 机载电脑 / Orin NX | 小范围、低速度、遥控器可接管条件下验证 |
| 回仓库 | NX 或个人电脑 | 只把验证过的代码提交/同步回仓库 |

核心原则：

1. **不要再把“个人电脑改完再上传 NX”当主流程。**
2. **现在以机载电脑现场开发和验证为主。**
3. **仓库只保存确认过的版本，不保存一堆未验证的临时改动。**
4. **飞行相关修改必须先拆桨验证，再考虑带桨。**
5. **定位、控制、起飞脚本相关修改，必须保留可回退版本。**

推荐一句话记忆：

```text
先在 NX 上跑通，再回仓库留版本。
```

## 2. 当前机器分工

### 2.1 机载电脑 / Orin NX

机载电脑现在是主要开发环境。

它负责：

- 运行 ROS Noetic
- 连接 Pixhawk / PX4
- 连接 Livox MID360
- 运行 FAST-LIO2
- 运行 MAVROS
- 运行 `fastlio_to_mavros`
- 运行 EGO-Planner
- 运行 `px4ctrl`
- 直接使用 Codex 修改和验证代码

常用工作空间：

```text
~/catkin_ws
~/livox_ws
~/fast_lio2_ws
```

当前重点代码一般在：

```text
~/catkin_ws/src
~/catkin_ws/tools
```

### 2.2 仓库

仓库负责长期保存版本。

仓库可以是：

- NX 本机上的 Git 仓库
- 个人电脑上的本地仓库，例如旧文档里的 `D:\repos\slam-drone`
- 后续接入的 GitHub / Gitee 私有仓库

现在仓库的定位是：

```text
仓库不是试错现场；仓库是验证后的版本记录。
```

### 2.3 个人电脑

个人电脑现在主要用于：

- SSH 登录 NX
- NoMachine 远程桌面
- 拉回验证过的代码
- 拉回 rosbag
- 做备份、整理文档、提交远程仓库

个人电脑不再作为唯一主开发入口。

## 3. 在机载电脑上直接开发

### 3.1 进入工作空间

在 NX 终端里：

```bash
cd ~/catkin_ws
```

如果当前目录本身就是 Git 仓库，先看状态：

```bash
git status -sb
```

如果 `~/catkin_ws` 不是仓库，而仓库在别的位置，也要先确认这次改的是哪一份代码，避免改错目录。

### 3.2 常改位置

| 位置 | 作用 | 改完是否通常要编译 |
| --- | --- | --- |
| `~/catkin_ws/src/fastlio_to_mavros` | FAST-LIO2 到 MAVROS 位姿桥接 | Python 不一定，C++ 要 |
| `~/catkin_ws/src/ego_planner/launch` | EGO-Planner 启动和参数 | 通常不用 |
| `~/catkin_ws/src/px4ctrl/config` | 控制参数、重量、悬停油门 | 通常不用 |
| `~/catkin_ws/tools` | 一键启动、录包、检查脚本 | 通常不用 |
| `~/catkin_ws/src/*/src` | C++ 源码 | 要编译 |
| `~/catkin_ws/src/*/package.xml` | ROS 包依赖 | 要编译 |
| `~/catkin_ws/src/*/CMakeLists.txt` | 编译规则 | 要编译 |

### 3.3 修改前先确认目标

每次让 Codex 改代码前，建议先用一句话说清楚：

```text
这次只改哪个文件、解决什么问题、不要动哪些主链路。
```

例如：

```text
只改 start_uav_stack.sh 的启动顺序，不改 FAST-LIO2 和 px4ctrl 源码。
```

这样可以降低临赛期间把主链路改乱的风险。

## 4. 改完代码后如何编译和重启

### 4.1 不需要重新编译的情况

一般不需要重新 `catkin_make`：

- 只改 `.py`
- 只改 `.launch`
- 只改 `.yaml`
- 只改 `.sh`
- 只改 `.md`

通常只需要：

```bash
source /opt/ros/noetic/setup.bash
source ~/catkin_ws/devel/setup.bash
```

然后重启对应节点或脚本。

### 4.2 需要重新编译的情况

需要重新编译：

- 改了 C++ 源码
- 改了 `CMakeLists.txt`
- 改了 `package.xml`
- 新增/修改了 ROS 消息、服务、动作定义

编译命令：

```bash
cd ~/catkin_ws
catkin_make
source ~/catkin_ws/devel/setup.bash
```

### 4.3 常用启动命令

基础链路：

```bash
bash ~/catkin_ws/tools/start_uav_stack.sh
```

规划和控制链路：

```bash
bash ~/catkin_ws/tools/start_planner_stack.sh
```

自动起飞：

```bash
bash ~/catkin_ws/tools/px4ctrl_takeoff.sh
```

自动降落：

```bash
bash ~/catkin_ws/tools/px4ctrl_land.sh
```

详细启动说明参考：[[03_竞赛资料/2026电赛D题无人机资料/slam-drone/历史开发文档/常用启动命令1.md]]、[[03_竞赛资料/2026电赛D题无人机资料/slam-drone/历史开发文档/EGO-Planner_FAST-LIO2接入说明.md]]。

## 5. 验证过的代码如何返回仓库

现在主方向是：

```text
NX 上开发验证 -> 返回仓库
```

不是：

```text
个人电脑改代码 -> 上传 NX 测试
```

### 5.1 如果 NX 上的工作空间本身就是 Git 仓库

在 NX 上执行：

```bash
cd ~/catkin_ws
git status -sb
```

确认只包含这次想保存的改动后：

```bash
git add src/fastlio_to_mavros tools *.md
git commit -m "说明这次验证过的改动"
```

如果已经配置远程仓库：

```bash
git push
```

稳定版本可以打标签：

```bash
git tag -a v1-stable -m "说明这个稳定版本"
git push --tags
```

### 5.2 如果最终仓库在个人电脑上

在个人电脑 PowerShell 里，先设置 NX 地址。把 IP 换成当前实际热点 IP：

```powershell
$NX="password123456@你的NX热点IP"
```

把验证过的代码从 NX 拉回个人电脑仓库：

```powershell
scp -r ${NX}:~/catkin_ws/src/fastlio_to_mavros "D:/repos/slam-drone/catkin_ws/src/"
scp -r ${NX}:~/catkin_ws/tools "D:/repos/slam-drone/catkin_ws/"
scp ${NX}:~/catkin_ws/*.md "D:/repos/slam-drone/catkin_ws/"
```

然后在个人电脑仓库里提交：

```powershell
cd D:\repos\slam-drone
git status -sb
git add catkin_ws/src/fastlio_to_mavros
git add catkin_ws/tools
git add catkin_ws/*.md
git commit -m "回收 NX 上验证过的开发改动"
```

如果有远程仓库：

```powershell
git push
```

### 5.3 回仓库前必须检查

回仓库前先确认：

- 这次代码是否至少在地面拆桨条件下跑过
- 如果涉及飞控/定位/控制，是否经过安全验证
- 有没有把 `build/`、`devel/`、`log/`、`.bag`、大点云一起带回仓库
- 有没有误提交临时日志、缓存文件、无关截图

不建议放进 Git 的内容：

```text
build/
devel/
log/
*.bag
大地图点云
临时输出文件
```

## 6. SSH 使用方法统一说明

SSH 现在主要用于：

1. 从个人电脑远程进入 NX 查状态
2. 从个人电脑拉回验证过的代码
3. 从个人电脑拉回 rosbag
4. 必要时远程执行简单命令
5. 备用情况下，把个人电脑仓库内容推到 NX

### 6.1 获取 NX 当前 IP

在 NX 终端执行：

```bash
hostname -I
```

如果输出类似：

```text
192.168.1.50 10.234.68.127
```

一般判断：

- `192.168.1.x` 可能是雷达有线网口
- `10.x.x.x` 常常是手机热点或 Wi-Fi
- SSH / NoMachine 通常优先用手机热点或 Wi-Fi IP

辅助查看：

```bash
nmcli device status
ip -4 addr
```

### 6.2 确认 NX 的 SSH 服务正常

在 NX 上执行：

```bash
sudo systemctl status ssh --no-pager
ss -tnlp | grep :22
```

需要看到：

- `ssh.service` 是 `active (running)`
- `22` 端口处于监听状态

如果 SSH 没启动：

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable ssh
sudo systemctl restart ssh
```

### 6.3 从个人电脑连接 NX

在个人电脑 PowerShell 里：

```powershell
ssh 用户名@NX的IP
```

如果用户名仍是 `password123456`，当前热点 IP 是 `10.234.68.127`，示例：

```powershell
ssh password123456@10.234.68.127
```

快速测试：

```powershell
ssh password123456@10.234.68.127 "echo SSH_OK"
```

如果输出：

```text
SSH_OK
```

说明 SSH 通道正常。

### 6.4 从个人电脑测试 SSH 端口

```powershell
Test-NetConnection 10.234.68.127 -Port 22
```

如果 `TcpTestSucceeded` 是 `True`，说明端口可达。

### 6.5 SSH 连不上时先查这些

1. NX 和个人电脑是否连到同一个手机热点 / Wi-Fi
2. NX 的 IP 是否已经变化
3. 你用的是不是热点 IP，而不是雷达网口 IP
4. SSH 服务是否启动
5. 雷达网口插上后，是否导致路由变化
6. 防火墙或网络共享是否拦截了 22 端口

### 6.6 用 SSH 远程执行简单命令

查看 NX 当前目录：

```powershell
ssh password123456@你的NX热点IP "pwd && hostname -I"
```

创建目录：

```powershell
ssh password123456@你的NX热点IP "mkdir -p ~/catkin_ws/src ~/catkin_ws/tools ~/catkin_ws/rosbags"
```

给脚本执行权限：

```powershell
ssh password123456@你的NX热点IP "chmod +x ~/catkin_ws/tools/*.sh"
```

### 6.7 从 NX 拉回验证过的代码

这是当前更常用的方向。

```powershell
$NX="password123456@你的NX热点IP"
scp -r ${NX}:~/catkin_ws/src/fastlio_to_mavros "D:/repos/slam-drone/catkin_ws/src/"
scp -r ${NX}:~/catkin_ws/tools "D:/repos/slam-drone/catkin_ws/"
scp ${NX}:~/catkin_ws/*.md "D:/repos/slam-drone/catkin_ws/"
```

### 6.8 从 NX 拉回 rosbag

```powershell
scp -r password123456@你的NX热点IP:~/catkin_ws/rosbags "D:/repos/slam-drone/catkin_ws/"
```

### 6.9 备用：从个人电脑推代码到 NX

这个是旧流程，只在下面情况使用：

- NX 上的代码被误删
- 需要恢复个人电脑仓库里的某个版本
- 机载电脑上暂时不方便用 Codex

```powershell
ssh password123456@你的NX热点IP "mkdir -p ~/catkin_ws/src ~/catkin_ws/tools"
scp -r "D:/repos/slam-drone/catkin_ws/src/fastlio_to_mavros" password123456@你的NX热点IP:~/catkin_ws/src/
scp -r "D:/repos/slam-drone/catkin_ws/tools" password123456@你的NX热点IP:~/catkin_ws/
ssh password123456@你的NX热点IP "chmod +x ~/catkin_ws/tools/*.sh"
```

如果要恢复旧的批处理脚本方式，见 [[#12. 旧开发流程归档|12. 旧开发流程归档]]。

## 7. NoMachine 使用和排障

NoMachine 现在主要用于图形界面：

- RViz
- QGC
- 多终端窗口
- 现场观察和手动操作

如果 NoMachine 连不上，但 SSH 还能通，优先通过 SSH 查状态，不要急着重装。

### 7.1 查看 NoMachine 服务状态

```bash
sudo /usr/NX/bin/nxserver --status
```

### 7.2 查看 NoMachine 端口

```bash
ss -tnlp | grep :4000
```

### 7.3 查看 NoMachine 进程

```bash
ps -ef | grep nx
```

### 7.4 查看最近日志

```bash
sudo tail -n 50 /usr/NX/var/log/nxserver.log
```

### 7.5 重启 NoMachine

```bash
sudo /usr/NX/bin/nxserver --restart
sudo /usr/NX/bin/nxserver --status
```

### 7.6 从个人电脑测试 NoMachine 端口

```powershell
Test-NetConnection 你的NX热点IP -Port 4000
```

如果 22 端口通、4000 端口不通：

- SSH 仍可用于查日志、拉代码、拉 rosbag
- NoMachine 可以后面再修

## 8. Git 最小使用流程

### 8.1 Git 负责什么

Git 负责记录：

- 代码改了什么
- 什么时候改的
- 哪个版本验证过
- 改坏后怎么回退

现在的重点不是学完整 Git，而是形成习惯：

```text
每完成一个小的、验证过的修改，就提交一次。
```

### 8.2 常用命令

查看状态：

```bash
git status -sb
```

查看具体改动：

```bash
git diff
```

加入改动：

```bash
git add 路径
```

提交：

```bash
git commit -m "说明这次改了什么"
```

查看历史：

```bash
git log --oneline --decorate -10
```

打稳定标签：

```bash
git tag -a v1-stable -m "说明这个稳定版本"
```

### 8.3 什么时候适合 commit

适合提交的时机：

- 桥接脚本能稳定运行
- 一键启动脚本跑通
- EGO-Planner 参数经过地面验证
- px4ctrl 参数经过小范围验证
- 第一次稳定悬停后
- 某次试飞前的安全版本
- 某次试飞后的确认版本

不建议提交：

- 刚改完但没运行过
- 飞机表现异常但还没定位原因
- 混入大量无关日志和 rosbag

## 9. 当前 PX4 飞控侧关键背景配置

根据当前项目的既有做法，飞控侧有几个关键前提。

### 9.1 推荐固件版本

当前经验上更稳定的实验固件是：

- `PX4 1.13.3`
- 对应板卡文件常见为：`px4-fmuv6c`

### 9.2 当前 EKF2 关键参数

在地面站 / QGC 中，当前主要依赖：

#### `EKF2_AID_MASK = 24`

目的：

- 在无 GPS 情况下，允许飞控依赖外部视觉/雷达位姿进入 `Position` 模式

#### `EKF2_HGT_MODE = vision`

目的：

- 让飞控高度估计更多依赖视觉/雷达高度

### 9.3 这两个参数带来的直接后果

试飞前不能只看：

- 雷达有没有点云
- FAST-LIO2 有没有出 `/Odometry`

还必须额外确认：

1. 飞控是否真的收到了 `/mavros/vision_pose/pose`
2. 飞控融合后的 `/mavros/local_position/pose` 是否正常
3. 高度 z 是否稳定
4. 无 GPS 情况下 `Position` 模式是否能切进去

也就是说：

```text
算法侧正常，不等于飞控融合侧正常。
```

## 10. 当前项目推荐的起飞前检查顺序

### 第一步：地面站确认

确认：

- 固件版本正确
- `EKF2_AID_MASK = 24`
- `EKF2_HGT_MODE = vision`
- 没有明显 EKF 报警
- 遥控器接管/急停可用

### 第二步：ROS 侧确认链路

```bash
rostopic echo -n 1 /mavros/state
rostopic hz /Odometry
rostopic hz /mavros/vision_pose/pose
rostopic echo -n 1 /mavros/local_position/pose
```

### 第三步：重点看 z 值

```bash
rostopic echo /Odometry
rostopic echo /mavros/vision_pose/pose
rostopic echo /mavros/local_position/pose
```

重点看：

- z 是否跳变
- z 是否缓慢漂移
- `/Odometry` 和 `/mavros/local_position/pose` 是否方向一致

### 第四步：RViz 看空间关系

重点看：

- `Odometry`
- `Path`
- `curr_points`
- `surround`
- `/Laser_map`
- `/cloud_registered`

### 第五步：地面试切 Position 模式

如果切不进去，或者切进去马上退出，说明当前“无 GPS + 外部视觉定位”条件还没满足，先不要起飞。

### 第六步：规划控制小范围验证

第一次不要直接跑完整任务。建议顺序：

```text
拆桨检查 -> 自动起飞逻辑检查 -> 小目标点 -> 悬停 -> 降落
```

带桨后也先只做：

```text
自动起飞 -> 悬停 -> 1 到 2 米小目标点 -> 自动降落
```

## 11. ROS 录包与数据回传

试飞时，不要只靠终端截图。优先录 `rosbag`。

### 11.1 轻量包和完整包

轻量包 `light` 适合每次试飞都开，主要看：

- 飞控模式
- 遥控输入
- `/Odometry`
- `/mavros/vision_pose/pose`
- `/mavros/local_position/pose`
- `/mavros/setpoint_raw/attitude`
- `/position_cmd`
- `/debugPx4ctrl`

完整包 `full` 适合排查点云、FAST-LIO2 和条带飞出去的问题，额外记录：

- `/livox/lidar`
- `/livox/imu`
