# 队员分工看板

> 当前实际情况：我们一共有两个队、六个队员。虽然还有一些备用硬件可以尝试组装二号机，但二号机需要重新学习和适配硬件，时间风险比较大。  
>武老师的策略是：**先保证一架飞机，也就是一号机，能够稳定参加测评。**  
> 所以当前分工以“一号机能完成任务”为第一优先级，二队更多作为通信、结构和备份支援。

---

## 1. 总体策略

### 第一优先级：一号机能上场

一号机必须优先完成：

- [ ] Pixhawk 4 + Orin NX + MID360 / FAST-LIO2 室内定位稳定；
- [ ] 无人机能在室内定点悬停；
- [ ] 无人机能起飞、悬停、返航、降落；
- [ ] 无人机能用视觉识别小车平台；
- [ ] 小车能一键启动并循线跑一圈；
- [ ] 小车能和无人机/地面站通信；
- [ ] 抛投机构能被无人机端控制。

### 第二优先级：二号机/备用硬件不要拖累主线

二号机相关工作可以做，但不能影响一号机进度。

二号机定位：

```text
备份方案 / 结构验证 / 通信支援 / 零部件备用
```

不是当前主参赛核心。

- 小车速度档位控制。

### 今天优先交付

- [ ] 确认 ESP32-S3 能否直接控制当前电机驱动；
- [ ] 确认循线传感器能否接入 ESP32-S3；

## 4. 地面站工作归属

地面站由负责通信/地面站的队友推进，当前最低目标是：

- [ ] 地面站电脑通过 USB 连接地面端 ESP32；
- [ ] 能看到小车发来的状态；
- [ ] 能看到无人机发来的状态；
- [ ] 能显示任务计时；
- [ ] 能显示小车和无人机的大概位置；
- [ ] 比赛现场不需要联网。

地面站可以先不用做复杂界面。第一版只要能稳定显示文字状态和基础位置即可。

## 5. 今日最小闭环目标

今天最重要的不是把所有功能做完，而是先形成最小闭环：

```text
小车按键启动
  -> 小车开始循线
  -> 小车 ESP32 发启动消息
  -> 无人机端 ESP32 收到
  -> Orin NX 收到启动消息
  -> 地面站收到并显示小车状态
```

同时无人机主线要做到：

```text
室内定位稳定
  -> 能低高度悬停
  -> 能看到小车平台图案
```

只要这两条线跑通，后续再接：

```text
伴飞 -> 抛投 -> 返航 -> 动态降落
```

## 7. 当前原则

1. **先保一号机参赛。**
2. **二号机和备用硬件不要抢主线时间。**
3. **小车先跑起来，再谈复杂定位。**
4. **通信先能收发，再谈协议美化。**
5. **地面站先能显示，再谈界面好看。**
6. **无人机先室内定点，再谈伴飞和抛投。**
