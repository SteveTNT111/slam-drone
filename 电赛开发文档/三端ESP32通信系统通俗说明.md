# 三端 ESP32 通信系统设想（通俗版）

> 这份文档不是代码设计，也不是最终协议规范。  
> 它只是把目前的通信设想整理成队友能快速理解的版本，方便讨论分工。

---

## 1. 我们现在想解决什么问题

这道题里面有三端：

1. 小车；
2. 无人机；
3. 地面站电脑。

这三端之间需要互相传信息，例如：

- 小车启动后，要通知无人机起飞；
- 小车要告诉地面站自己当前状态和大概位置；
- 无人机要告诉地面站自己当前状态和位置；
- 无人机上的机载电脑要能控制抛投器；
- 地面站要能把小车和无人机的状态显示出来。

我们希望这个通信系统**不依赖网络、不需要联网、不需要路由器**，比赛现场直接自己通信。

---

## 2. 为什么考虑全部用 ESP32

目前小车原本用的是 TI 芯片做底盘运动控制。问题是：

- TI 芯片通信这块不方便；
- 我不熟悉 TI 开发；
- 如果还要在 TI 上做无线通信，调试成本比较高。

所以和武老师讨论后，有一个想法：

> 看能不能在一天内，把小车底盘控制改成用普通 ESP32 来做。

这样做的好处是：

- ESP32 本身能做无线通信；
- 可以使用 ESP-NOW；
- ESP-NOW 不需要联网；
- 三块 ESP32 可以自组网；
- 小车、无人机、地面站都可以用同一种通信方式；
- 开发和调试可能比 TI 通信更快。

---

## 3. 三块 ESP32 分别放在哪里

我们计划用三块 ESP32：

```text
小车上一块 ESP32
无人机上一块 ESP32
地面站电脑旁边一块 ESP32
```

整体关系是：

```text
小车 ESP32  <——ESP-NOW——>  无人机 ESP32  <——ESP-NOW——>  地面站 ESP32

无人机 ESP32  <——USB 串口——>  Orin NX 机载电脑

地面站 ESP32  <——USB 串口——>  地面站电脑
```

---

## 4. 小车端 ESP32 要做什么

小车端 ESP32 需要负责两类事情。

### 第一类：控制小车底盘

也就是原来 TI 芯片做的事情：

- 按键启动；
- 黑线循迹；
- 控制电机；
- 控制小车跑一圈；
- 回到 A 点后停车；
- 不同任务下切换不同运行逻辑。

### 第二类：无线通信

小车端 ESP32 还要通过 ESP-NOW 发消息，例如：

- 小车启动了；
- 小车正在运行；
- 小车大概到哪里了；
- 小车当前速度/状态；
- 小车完成一圈了。

小车也可以接收无人机发来的简单指令，例如：

- 进入慢速；
- 恢复正常速度；
- 动态降落阶段保持低速行进。

---

## 5. 无人机端 ESP32 要做什么

无人机端 ESP32 不负责飞控算法，也不负责视觉识别。

无人机的主要计算仍然放在 Orin NX 小电脑上。

无人机端 ESP32 只负责无线通信中转。

### 无线通信中转

它通过 ESP-NOW 收到小车和地面站的无线消息，然后通过 USB 串口转发给 Orin NX。

同时，Orin NX 也可以通过 USB 串口把消息发给无人机端 ESP32，再由 ESP32 通过 ESP-NOW 转发出去。

简单理解：

```text
ESP-NOW 无线消息  <->  无人机 ESP32  <->  USB 串口  <->  Orin NX
```

### 抛投执行机构不再由 ESP32 控制

抛投执行机构直接连接 Pixhawk 飞控的空闲输出通道，由 Orin NX 上的 Python ROS 节点通过 MAVROS 请求 PX4 输出对应 PWM。

```text
Orin NX 判断可以抛投
  -> ROS 调用 MAVROS 执行机构控制节点
  -> MAVROS 将命令发送给 PX4
  -> Pixhawk 空闲输出通道控制抛投机构
  -> 抛投完成
```

ESP32 固件中不再包含抛投执行机构源文件、命令、GPIO、角度或 PWM 逻辑。

---

## 6. 地面站端 ESP32 要做什么

地面站电脑旁边也接一块 ESP32。

这块 ESP32 的任务很简单：

- 接收小车发来的无线消息；
- 接收无人机发来的无线消息；
- 通过 USB 串口发给地面站电脑；
- 如果地面站电脑要发指令，也通过它转发出去。

它不需要做复杂控制。

简单理解：

```text
ESP-NOW 无线消息  <->  地面站 ESP32  <->  USB 串口  <->  地面站电脑
```

---

## 7. 地面站电脑怎么显示

地面站电脑可以是普通笔记本，也可以是其他电脑。

它不需要联网。

它只需要通过 USB 线连接地面站 ESP32。

然后地面站软件从串口读取数据，把收到的信息显示出来，例如：

- 小车当前状态；
- 小车大概位置；
- 无人机当前状态；
- 无人机位置；
- 是否正在伴飞；
- 是否已经抛投；
- 是否正在返航/降落。

地面站可以用网页做，也可以用其他方式做。

如果用网页做，大概就是：

```text
打开一个本地网页
浏览器连接 ESP32 串口
网页读取串口数据
网页画出小车和无人机位置
```

这块由负责地面站的队友决定。

## 8. 三端通信的大概逻辑

### 小车启动时

```text
小车按键启动
  -> 小车 ESP32 控制小车开始循线
  -> 小车 ESP32 通过 ESP-NOW 发出“小车已启动”消息
  -> 无人机 ESP32 收到消息
  -> 无人机 ESP32 通过串口告诉 Orin NX
  -> Orin NX 开始无人机起飞流程
  -> 地面站 ESP32 也收到消息
  -> 地面站电脑显示“小车已启动”
```

### 小车运行时

```text
小车 ESP32 持续发送小车状态
  -> 地面站显示小车位置/状态
  -> 无人机也可以根据小车状态辅助判断任务阶段
```

### 无人机运行时

```text
Orin NX 计算无人机状态和位置
  -> 通过串口发给无人机 ESP32
  -> 无人机 ESP32 通过 ESP-NOW 发给地面站
  -> 地面站显示无人机位置/状态
```

### 抛投时

```text
Orin NX 通过视觉判断已经对准小车平台
  -> ROS 通过 MAVROS 请求 PX4 控制空闲输出通道
  -> Pixhawk 控制抛投机构释放
  -> ROS 更新“抛投完成”状态
  -> 通过无人机 ESP32 广播状态给地面站
  -> 地面站显示“抛投完成”
```

### 动态降落时

```text
小车到 B 点后继续运动
  -> 无人机开始寻找/对准小车平台
  -> 如果需要，小车可以切到慢速行进
  -> 无人机降落到小车平台
  -> 停留 5 秒
  -> 无人机再起飞返航
  -> 小车继续跑完一圈
```

## 9. 关于“小车位置”的想法

小车不一定需要装激光雷达。

因为小车只是在固定黑线轨道上运行，它的轨迹是已知的。

所以小车位置可以用比较简单的方法估计：

### 方法 1：按时间估计

如果小车每次跑的速度基本一样，那么可以根据启动后的时间，大概估计小车在轨迹上的位置。

例如：

```text
启动后几秒在 A-B 段
再过一段时间到 B 点附近
再过一段时间到 C 点附近
```

### 方法 2：用编码器积分

如果小车电机有编码器，就可以根据轮子转了多少，估算小车沿轨迹走了多远。

这样可以更准确地知道小车当前在轨迹上的进度。

### 方法 3：小车自己发区段状态

小车可以简单告诉其他端：

```text
我刚启动
我在 A-B 段
我到 B 点了
我在 B-D 段
我到 D 点了
我快回 A 了
我已完成
```

地面站不一定需要特别精确的坐标，先能显示大概位置和状态就行。

## 10. 为什么同一信道通信也可以

三块 ESP32 都在同一个 ESP-NOW 信道上通信。

这意味着地面站 ESP32 可能会收到所有消息。

这没关系。

只要每条消息里写清楚：

- 这条消息是谁发的；
- 这条消息是发给谁的；
- 这条消息是什么意思。

那么收到消息的一端就可以判断：

```text
如果是发给我的，我就处理；
如果不是发给我的，我就忽略；
如果是广播消息，地面站就拿来显示。
```

所以我们不怕“串屏”，关键是消息格式要统一。

---

## 11. 这套方案的优点

1. 不需要联网；
2. 不需要路由器；
3. 小车、无人机、地面站三端通信方式统一；
4. 地面站电脑只需要接 USB 串口；
5. 无人机 Orin NX 也只需要通过 USB 串口和 ESP32 通信；
6. 抛投执行机构由 Pixhawk/PX4 直接控制，ESP32 通信职责更单一；
7. 地面站可以先做得很简单，先显示数据，再慢慢美化。

---

## 12. 当前需要队友确认的事情

### 小车负责人需要确认

- 能不能一天内把 TI 底盘控制改成 ESP32 控制；
- ESP32 能不能稳定读取循线传感器；
- ESP32 能不能控制当前电机驱动；
- 小车有没有编码器；
- 如果没有编码器，能不能先用时间估计位置。

### 无人机负责人需要确认

- 无人机上 ESP32 通过 CH340 USB 串口能否稳定被 Orin NX 识别；
- Orin NX 能否用 Python/ROS 节点读写这个串口；
- Pixhawk 的空闲输出口、PX4 输出映射和 MAVROS 控制命令是否已实机确认；
- 抛投执行机构的外部供电、共地、PWM 范围和机械限位是否安全。

### 地面站负责人需要确认

- 地面站是用网页、Qt，还是其他方式实现；
- 如果用网页，浏览器能不能连接 ESP32 串口；
- 地面站只负责显示，还是也需要发送测试指令；
- 地面站界面要显示哪些状态。

---

## 13. 最简实现目标

如果时间很紧，第一版只要做到：

```text
小车 ESP32：按键后发“小车启动”和“小车状态”
无人机 ESP32：收到小车消息后转发给 Orin NX；把 NX 状态消息通过 ESP-NOW 广播出去
地面站 ESP32：收到所有消息后转发给电脑
地面站电脑：把收到的文字消息显示出来
```

先让三端通信跑通，再谈更复杂的位置显示和状态机。
