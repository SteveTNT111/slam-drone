## 最直接的答案

### 1. PX4收到SLAM视觉位姿后，不是直接复制成NED

实际过程是：

```text
飞控IMU持续积分
→ PX4 EKF2预测姿态、速度和NED位置
→ 接收SLAM外部视觉位姿
→ EKF2使用视觉位置/高度/可选yaw修正内部状态
→ PX4继续维护自己的local position
→ MAVROS发布/mavros/local_position/pose
```

text

PX4官方说明，外部视觉位姿用于更新飞控的本地位置估计；外部视觉坐标与PX4估计器坐标的航向通常并不天然一致，必要时需要自定义变换。([docs.px4.io](https://docs.px4.io/v1.13/en/ros/external_position_estimation.html))

---

### 2. 不能一上来就直接发送SLAM的`[0.5,0,1]`

只有实测证明：

```text
SLAM map原点
=
MAVROS local原点

SLAM +X
=
MAVROS local +X

SLAM +Y
=
MAVROS local +Y

SLAM +Z
=
MAVROS local +Z

SLAM yaw=0
=
MAVROS local yaw=0
```

text

才可以直接发送：

```text
起飞：
[0.0, 0.0, 1.0, 0.0]

前进0.5m：
[0.5, 0.0, 1.0, 0.0]
```

text

虽然你们已经把飞机物理摆正，让机头沿场地长边、SLAM `+X` 指向机头前方，但这只能确定**物理基准**，不能保证 PX4 EKF2 的 local 原点和 yaw 数值也正好为零。

PX4官方同样强调，应先把机体局部X轴与外部定位世界X轴对齐，否则会存在yaw偏差并影响外部位姿融合。([docs.px4.io](https://docs.px4.io/v1.13/en/ros/external_position_estimation.html))

---

## 推荐实际发送方式

系统稳定后先读取：

```text
x0 = 当前/mavros/local_position/pose.x
y0 = 当前/mavros/local_position/pose.y
z0 = 当前/mavros/local_position/pose.z
yaw0 = 当前MAVROS local yaw
```

text

### 起飞到相对1米

持续发送：

```text
x = x0
y = y0
z = z0 + 1.0
yaw = yaw0
```

text

即：

```text
[x0, y0, z0+1.0, yaw0]
```

text

### 沿初始机头方向前进0.5米

持续发送：

```text
x = x0 + 0.5*cos(yaw0)
y = y0 + 0.5*sin(yaw0)
z = z0 + 1.0
yaw = yaw0
```

text

也就是：

```text
[
  x0 + 0.5*cos(yaw0),
  y0 + 0.5*sin(yaw0),
  z0 + 1.0,
  yaw0
]
```

text

如果拆桨测试确认：

```text
yaw0 ≈ 0
SLAM +X 与 MAVROS local +X 数值一致
```

text

那么才可以简化成：

```text
[x0+0.5, y0, z0+1.0, yaw0]
```

text

## 不需要Python手工转换成NED

控制节点发布：

```text
/mavros/setpoint_position/local
```

text

这里使用的是 ROS/MAVROS local 坐标语义。

MAVROS负责标准的：

```text
ROS ENU
↔
PX4 NED
```

text

转换。ROS世界坐标通常是 ENU/向上为正，PX4内部使用NED/向下为正。PX4官方明确说明，在MAVROS链路中应向ROS侧提供ENU位姿，由MAVROS处理NED转换。([docs.px4.io](https://docs.px4.io/v1.13/en/ros/external_position_estimation.html))

所以不要在Python里再做：

```text
交换X/Y
Z取负
再发送给MAVROS
```

text

否则可能重复转换。

真正需要我们做的是：

```text
比赛/SLAM任务坐标
→ 原点平移和水平yaw旋转
→ MAVROS local坐标
```

text

而不是：

```text
MAVROS local
→ 手工NED转换
```

text

转换。

## 怎么判断能不能直接发送

拆桨后同时打开三个终端：

```bash
rostopic echo /Odometry/pose/pose/position
```

bash

```bash
rostopic echo /mavros/vision_pose/pose/pose/position
```

bash

```bash
rostopic echo /mavros/local_position/pose/pose/position
```

bash

然后把飞机沿初始机头方向手动移动约 `0.30 m`。

### 如果三路都是

```text
x增加约0.30m
y基本不变
```

text

说明：

```text
SLAM +X
≈
MAVROS local +X
```

text

可以考虑直接对应。

### 如果出现

```text
SLAM x增加
MAVROS local y增加
```

text

说明存在固定水平旋转，必须转换。

### 如果方向相反

说明存在：

- 坐标反号；
- 桥接错误；
- yaw对齐错误；
- 重复ENU/NED转换。

### 如果差异随着时间或飞机旋转变化

说明不是简单的固定旋转问题，应先检查：

- FAST-LIO外参；
- 桥接位置和四元数是否使用同一个变换；
- vision yaw融合；
- 磁力计航向冲突；
- 时间戳和延迟；
- EKF2融合状态。
